🔴 CRITICAL ISSUES (Must Fix Before Production)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  1. Dual Framework Migration (Flask + FastAPI) - INCOMPLETE
     └─ Impact: Maintenance nightmare, unclear source of truth
  
  2. Video Support is Rudimentary
     ├─ No metadata extraction (duration, codec, bitrate)
     ├─ Fragile ffmpeg dependency (hardcoded paths)
     ├─ No streaming support (HLS/DASH)
     ├─ No browser player UI
     └─ Impact: Large videos fail silently, unusable for video libraries
  
  3. Exception Handling is Inadequate
     ├─ 16+ bare `except Exception:` blocks with no logging
     ├─ Silent failures (users see emoji placeholders)
     ├─ Lost stack traces (impossible to debug production issues)
     └─ Impact: Production incidents undetectable

⚠️  HIGH PRIORITY ISSUES (Fix This Sprint)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  4. No Structured Logging
     └─ All errors logged with print() → lost in production
  
  5. Search Limitations
     ├─ Only 24 Chinese cities in CITY_ALIASES (should be 300+)
     ├─ No full-text search (just LIKE %term%)
     ├─ Exponential OR conditions slow with alias expansion
     └─ Person query detection hits DB per search (should cache)
  
  6. Input Validation Missing
     └─ int() conversion not wrapped → ValueError unhandled
  
  7. Database Indices Missing
     ├─ No index on gps_city, filename, directory, taken_at
     └─ Search performance degrades with >10k photos
  
  8. Pagination Inefficient
     ├─ Offset-based (O(n) per page) instead of cursor-based
     ├─ Hardcoded max 200 limit
     └─ All results fetched, then sliced in memory
